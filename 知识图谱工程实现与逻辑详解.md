## 一、技术架构与选型

### 1.1 技术选型

**为什么选择轻量级实现？**

- **无需额外服务**：不需要部署 Neo4j 等图数据库，降低运维成本
- **快速启动**：使用 NetworkX + pickle，启动速度快
- **易于调试**：数据结构清晰，便于排查问题
- **适合中小规模**：对于接口依赖关系，节点和边数量通常在千级以内，NetworkX 完全够用

**技术栈**：
- **图结构**：NetworkX（Python 图论库）
- **持久化**：pickle（Python 序列化）
- **存储格式**：`.pkl` 文件（二进制格式）

### 1.2 架构设计

```
┌─────────────────────────────────────────┐
│   LightweightKnowledgeGraph             │
│   (轻量级知识图谱服务)                   │
├─────────────────────────────────────────┤
│  - NetworkX DiGraph (有向图)             │
│  - 节点：API接口                         │
│  - 边：依赖关系                           │
│  - 持久化：pickle (.pkl文件)             │
└─────────────────────────────────────────┘
           │                    │
           │                    │
    ┌──────▼──────┐      ┌──────▼──────┐
    │  查询逻辑    │      │  学习逻辑    │
    │             │      │             │
    │ - 前置依赖  │      │ - 执行后学习 │
    │ - 依赖链    │      │ - 置信度更新 │
    └─────────────┘      └─────────────┘
```

## 二、数据结构设计

### 2.1 节点（Node）结构

**节点ID格式**：
```
{project_id}:{method}:{path}
```

**示例**：
```
"default-project:POST:/api/login"
"default-project:GET:/api/user/profile"
"project-123:POST:/api/orders"
```

**节点属性（Node Attributes）**：
```python
{
    "node_type": "api",           # 节点类型，固定为 "api"
    "path": "/api/login",         # API路径
    "method": "POST",             # HTTP方法
    "name": "用户登录",           # API名称（可选）
    # ... 其他自定义属性
}
```

**代码实现**：
```python
# 添加节点
self.graph.add_node(api_id, **attributes, node_type='api')

# 节点ID构建函数
def _kg_node_id(project_id: str, step: Dict) -> str:
    m = str(step.get("api_method") or step.get("method") or "GET").upper()
    p = str(step.get("api_path") or step.get("path") or "")
    return f"{project_id}:{m}:{p}"
```

### 2.2 边（Edge）结构

**边表示依赖关系**：
```
from_api → to_api
```
含义：`from_api` 执行后，才能执行 `to_api`

**边属性（Edge Attributes）**：
```python
{
    "field_mapping": {                    # 字段映射关系（核心）
        "Authorization": "data.token",    # 目标字段: 源字段路径
        "userId": "data.userId",
        "sessionId@params": "data.sessionId"  # 支持指定类型：@params/@headers/@url_params
    },
    "count": 10,                          # 总调用次数
    "success_count": 9,                   # 成功次数
    "confidence": 0.9,                     # 置信度 = success_count / count
    "source_type": "execution",            # 来源类型：execution|doc|manual
    "source_id": "test_case_123",         # 来源ID（如test_case_id）
    "created_at": "2024-01-01T00:00:00",  # 创建时间
    "last_used": "2024-01-15T12:00:00"    # 最后使用时间
}
```

**置信度计算**：
```python
confidence = success_count / count
# 例如：9次成功 / 10次调用 = 0.9 (90%置信度)
```

#### 3.2.2 依赖关系管理

**添加依赖关系（核心方法）**：
```python
def add_dependency(
    self,
    from_api: str,          # 源API ID
    to_api: str,            # 目标API ID
    field_mapping: Dict = None,  # 字段映射关系
    source_type: str = "execution",  # 来源类型
    source_id: Any = None,  # 来源ID
    success: bool = True,   # 本次是否成功
    **attributes,
):
    """
    添加API依赖关系
    
    逻辑：
    1. 检查节点是否存在
    2. 如果边已存在：更新计数和置信度
    3. 如果边不存在：创建新边
    4. 持久化到文件
    """
    # 1. 验证节点存在
    if from_api not in self.graph:
        logger.warning(f"API节点不存在: {from_api}，跳过依赖记录")
        return
    if to_api not in self.graph:
        logger.warning(f"API节点不存在: {to_api}，跳过依赖记录")
        return
    
    fm = field_mapping or {}
    
    # 2. 如果边已存在：更新
    if self.graph.has_edge(from_api, to_api):
        edge = self.graph[from_api][to_api]
        edge['count'] = edge.get('count', 0) + 1  # 总次数+1
        edge['last_used'] = datetime.now().isoformat()
        
        # 更新成功次数
        if success:
            edge['success_count'] = edge.get('success_count', 0) + 1
        else:
            # 失败时降低置信度（最少为0）
            edge['success_count'] = max(0, edge.get('success_count', 0) - 1)
        
        # 合并字段映射（新映射覆盖旧）
        existing_fm = edge.get('field_mapping') or {}
        existing_fm.update(fm)
        edge['field_mapping'] = existing_fm
        
        if source_id:
            edge['last_source_id'] = source_id
        if source_type:
            edge['source_type'] = source_type
    
    # 3. 如果边不存在：创建新边
    else:
        self.graph.add_edge(
            from_api, to_api,
            field_mapping=fm,
            count=1,
            success_count=1 if success else 0,
            source_type=source_type or "execution",
            source_id=source_id,
            created_at=datetime.now().isoformat(),
            last_used=datetime.now().isoformat(),
            **attributes,
        )
    
    # 4. 持久化
    self.save_graph()
    logger.debug(f"添加依赖关系: {from_api} -> {to_api}")
```

**置信度更新机制**：
```python
# 成功执行
if success:
    edge['success_count'] += 1
    # 置信度 = (success_count + 1) / (count + 1)  # 提高

# 失败执行
else:
    edge['success_count'] = max(0, edge['success_count'] - 1)
    # 置信度 = (success_count - 1) / (count + 1)  # 降低（最少0）
```

#### 3.2.3 查询方法

**查询前置依赖（核心查询方法）**：
```python
def get_predecessors(
    self,
    api_id: str,                    # 目标API ID
    min_confidence: float = 0.5,    # 最小置信度阈值
    limit: int = 5,                  # 返回数量限制
) -> List[Dict]:
    """
    获取「谁在调用当前 API 之前」的前置依赖（入边）。
    
    用于：
    1. 单接口执行前依赖解析
    2. 场景用例执行前补全 param_mappings
    
    返回格式：
    [
        {
            "from_api": "default-project:POST:/api/login",
            "field_mapping": {"Authorization": "data.token"},
            "confidence": 0.9,
            "path": "/api/login",
            "method": "POST"
        },
        ...
    ]
    """
    if api_id not in self.graph:
        return []
    
    out = []
    # 遍历所有指向当前节点的边（前置依赖）
    for from_api in self.graph.predecessors(api_id):
        edge = self.graph[from_api][api_id]
        count = edge.get("count") or 0
        if count <= 0:
            continue
        
        # 计算置信度
        success_count = edge.get("success_count", 0)
        confidence = success_count / count
        
        # 过滤低置信度边
        if confidence < min_confidence:
            continue
        
        # 获取前置API的节点属性
        node_attrs = dict(self.graph.nodes[from_api])
        out.append({
            "from_api": from_api,
            "field_mapping": edge.get("field_mapping") or {},
            "confidence": round(confidence, 2),
            "path": node_attrs.get("path", ""),
            "method": node_attrs.get("method", "GET"),
        })
    
    # 按置信度降序排序
    out.sort(key=lambda x: (-x["confidence"],))
    return out[:limit]
```

**查询依赖边（用于场景生成）**：
```python
def get_edges_for_prompt(
    self,
    project_id: str,
    apis_for_prompt: List[Dict],
    min_confidence: float = 0.5,
    limit: int = 50,
) -> List[Dict]:
    """
    获取与当前候选 API 相关的依赖边，用于生成场景时的上下文增强。
    
    只返回：
    1. 两端节点都在 apis_for_prompt 中的边
    2. 置信度 >= min_confidence 的边
    
    用于场景生成时注入知识图谱依赖关系到Prompt中。
    """
    if not apis_for_prompt or not project_id:
        return []
    
    # 1. 构建节点ID集合
    node_ids = set()
    for a in apis_for_prompt:
        m = str(a.get("method") or "GET").strip().upper()
        p = str(a.get("path") or "").strip()
        if p:
            node_ids.add(f"{project_id}:{m}:{p}")
    
    if not node_ids:
        return []
    
    # 2. 遍历所有边，筛选符合条件的
    edges_out = []
    for u, v in self.graph.edges():
        if u not in node_ids or v not in node_ids:
            continue  # 两端不在候选列表中，跳过
        
        edge = self.graph[u][v]
        count = edge.get("count") or 0
        if count <= 0:
            continue
        
        # 计算置信度
        success_count = edge.get("success_count", 0)
        confidence = success_count / count
        if confidence < min_confidence:
            continue
        
        edges_out.append({
            "from_api": u,
            "to_api": v,
            "field_mapping": edge.get("field_mapping") or {},
            "confidence": round(confidence, 2),
            "count": count,
        })
    
    # 3. 按置信度和次数排序
    edges_out.sort(key=lambda x: (-x["confidence"], -x["count"]))
    return edges_out[:limit]
```

#### 3.2.4 持久化方法

**保存图谱**：
```python
def save_graph(self):
    """持久化图谱到文件"""
    try:
        os.makedirs(os.path.dirname(self.db_path), exist_ok=True)
        with open(self.db_path, 'wb') as f:
            pickle.dump(self.graph, f)  # 序列化NetworkX图对象
    except Exception as e:
        logger.error(f"保存知识图谱失败: {e}")

def load_graph(self):
    """从文件加载图谱"""
    try:
        if os.path.exists(self.db_path):
            with open(self.db_path, 'rb') as f:
                self.graph = pickle.load(f)  # 反序列化
        else:
            self.graph = nx.DiGraph()  # 创建新图
            logger.info("创建新的知识图谱")
    except Exception as e:
        logger.error(f"加载知识图谱失败: {e}, 创建新图谱")
        self.graph = nx.DiGraph()
```

**持久化时机**：
- 添加节点后：立即保存
- 添加/更新边后：立即保存
- 删除节点/边后：立即保存

**文件格式**：
- 格式：`.pkl`（Python pickle 二进制格式）
- 位置：`data/knowledge_graph.pkl`（相对于数据库路径）
- 大小：通常几KB到几MB（取决于节点和边数量）

### 4.1 单接口依赖解析流程

**调用入口**：`main_sqlite.py` 第1671-1674行

**完整流程**：

```python
async def _resolve_dependencies(
    steps: List[Dict],
    plan: Dict,
    project_id: str,
    db_path: str,
    ai_client: Any,
) -> List[Dict]:
    """
    自动依赖解析逻辑
    
    步骤：
    1. 检查缓存
    2. 跳过登录类接口
    3. ★ 知识图谱查询（优先）
    4. RAG检索（知识图谱无结果时）
    5. AI分析（RAG有结果时）
    6. 应用依赖链
    """
    
    # 步骤1：检查缓存
    cache_key = (project_id, method, path)
    if cache_key in _DEP_CACHE:
        return _apply_dep_chain(steps, _DEP_CACHE[cache_key], project_id, db_path)
    
    # 步骤2：跳过登录类接口
    login_keywords = ["login", "signin", "auth", "token", "verify-code", "register"]
    if any(k in path.lower() for k in login_keywords):
        return steps  # 登录接口本身不需要前置依赖
    
    # 步骤3：★ 知识图谱查询（优先）
    if _kg:
        try:
            # 构建节点ID
            node_id = f"{project_id}:{method}:{path}"
            
            # 查询前置依赖（置信度阈值0.5，最多返回5个）
            preds = _kg.get_predecessors(node_id, min_confidence=0.5, limit=5)
            
            if preds:
                # 构建依赖链
                chain = [
                    {
                        "api_path": p.get("path", ""), 
                        "api_method": (p.get("method") or "GET").upper(), 
                        "reason": "知识图谱前置"
                    }
                    for p in preds
                ]
                
                # 缓存结果
                _DEP_CACHE[cache_key] = chain
                
                # 直接应用依赖链，跳过后续RAG+AI流程
                return _apply_dep_chain(steps, chain, project_id, db_path)
        except Exception as _e:
            # 容错：知识图谱查询失败不影响主流程
            _dlog(f"知识图谱查询跳过: {_e}")
    
    # 步骤4：RAG检索（知识图谱无结果时）
    # ... RAG检索逻辑 ...
    
    # 步骤5：AI分析（RAG有结果时）
    # ... AI分析逻辑 ...
    
    # 步骤6：应用依赖链
    return _apply_dep_chain(steps, chain, project_id, db_path)
```

### 4.3 应用依赖链

**代码位置**：`main_sqlite.py` 第324-450行

**功能**：将知识图谱查询到的依赖链转换为真实的执行步骤

**流程**：
```python
def _apply_dep_chain(target_steps: List[Dict], chain: List[Dict], project_id: str, db_path: str) -> List[Dict]:
    """
    将依赖链转化为真实的执行步骤
    
    输入：
    - target_steps: 原始步骤列表
    - chain: 依赖链 [{"api_path": "/api/login", "api_method": "POST", "reason": "知识图谱前置"}]
    
    输出：
    - 新的步骤列表：前置步骤 + 原始步骤
    """
    if not chain:
        return target_steps
    
    conn = sqlite3.connect(db_path)
    cursor = conn.cursor()
    new_steps = []
    step_order_ptr = 1
    
    # 1. 为每个依赖接口创建执行步骤
    for dep in chain:
        d_path = dep.get("api_path")
        d_method = dep.get("api_method", "POST").upper()
        
        # 从数据库查询接口定义
        cursor.execute(
            "SELECT request_body, base_url, headers FROM apis WHERE project_id = ? AND path = ? AND method = ?",
            (project_id, d_path, d_method)
        )
        row = cursor.fetchone()
        
        if row:
            # 创建前置步骤
            new_step = {
                "step_order": step_order_ptr,
                "api_path": d_path,
                "api_method": d_method,
                "params": {},  # 根据接口定义填充
                "headers": {},
                "param_mappings": [],  # 前置步骤通常无依赖
                "description": f"[前置依赖] {dep.get('reason', '')}"
            }
            new_steps.append(new_step)
            step_order_ptr += 1
    
    # 2. 更新原始步骤的step_order
    for step in target_steps:
        step["step_order"] = step_order_ptr
        # 配置param_mappings（从知识图谱的field_mapping）
        # ... 配置逻辑 ...
        step_order_ptr += 1
    
    # 3. 合并：前置步骤 + 原始步骤
    return new_steps + target_steps
```

### 5.2 学习流程详解

**函数定义**：`main_sqlite.py` 第778-826行

```python
def _learn_steps_to_kg(project_id: str, steps: List[Dict], is_success: bool, source_id: Any = None):
    """
    从执行步骤学习依赖边到知识图谱
    
    输入：
    - project_id: 项目ID
    - steps: 执行步骤列表（已排序）
    - is_success: 是否执行成功
    - source_id: 来源ID（test_case_id）
    
    流程：
    1. 为每个步骤创建/确保节点存在
    2. 从param_mappings中提取依赖关系
    3. 为每个依赖关系创建/更新边
    4. 根据执行结果更新置信度
    """
    if not _kg or not steps or not project_id:
        return
    
    try:
        # 步骤1：排序步骤（按step_order）
        steps_sorted = sorted(steps, key=lambda s: int(s.get("step_order") or 0))
        node_ids = []
        
        # 步骤2：为每个步骤创建/确保节点存在
        for s in steps_sorted:
            nid = _kg_node_id(project_id, s)  # 构建节点ID
            node_ids.append(nid)
            
            # 确保节点存在（不存在则创建）
            _kg.ensure_api_node(
                nid,
                path=s.get("api_path") or s.get("path") or "",
                method=str(s.get("api_method") or s.get("method") or "GET").upper(),
                name=s.get("description") or s.get("api_name") or "",
            )
        
        # 步骤3：从param_mappings中提取依赖关系
        for i, s in enumerate(steps_sorted):
            mappings = s.get("param_mappings") or []
            if not mappings or i >= len(node_ids):
                continue
            
            to_nid = node_ids[i]  # 当前步骤的节点ID
            
            # 按from_step分组映射
            by_from = {}
            for m in mappings:
                if not isinstance(m, dict):
                    continue
                fs = m.get("from_step")  # 从哪个步骤
                ff = m.get("from_field")  # 从哪个字段
                tf = m.get("to_field")  # 映射到哪个字段
                tt = m.get("to_type") or "params"  # 映射类型
                
                if not fs or fs <= 0 or fs > len(node_ids):
                    continue
                
                from_idx = fs - 1  # step_order从1开始，数组索引从0开始
                from_nid = node_ids[from_idx]
                
                # 构建字段映射键（支持类型）
                key = f"{tf}@{tt}" if tt != "params" else tf
                by_from.setdefault(from_nid, {})[key] = ff
            
            # 步骤4：为每个依赖关系创建/更新边
            for from_nid, fm in by_from.items():
                _kg.add_dependency(
                    from_nid,
                    to_nid,
                    field_mapping=fm,
                    source_type="execution",
                    source_id=source_id,
                    success=is_success  # 根据执行结果更新置信度
                )
    except Exception as e:
        print(f"知识图谱学习跳过: {e}")
        # 容错：学习失败不影响主流程
```

## 九、总结

### 9.1 核心要点

1. **轻量级实现**：使用NetworkX + pickle，无需额外数据库服务
2. **节点ID格式**：`{project_id}:{method}:{path}`
3. **边表示依赖**：`from_api → to_api`，包含字段映射和置信度

6. **置信度机制**：成功提高，失败降低，低置信度自动过滤

## 十、常见问题

### Q1: 知识图谱文件损坏怎么办？

**A**: 系统会自动检测并创建新图。如果文件损坏，会在日志中记录错误，然后创建新的空图。

### Q2: 如何查看知识图谱的内容？

**A**: 可以使用 `export_project_subgraph()` 方法导出项目的子图，查看节点和边。

### Q3: 如何手动修正错误的依赖关系？

**A**: 可以使用 `remove_dependency()` 方法删除错误的边，或者通过API重建知识图谱。

### Q4: 知识图谱会影响性能吗？

**A**: 不会。NetworkX对于千级节点和边的图，查询速度很快（毫秒级）。持久化使用pickle，也是高效的。

### Q5: 如何重置知识图谱？

**A**: 删除 `knowledge_graph.pkl` 文件，系统会自动创建新图。

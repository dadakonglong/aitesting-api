# 知识图谱说明

知识图谱用于记录接口间的依赖关系，为生成场景用例、执行补全提供上下文增强。

## 如何确认图谱是否启用

1. **启动时看控制台**  
   运行 `python services/ai-processing/main_sqlite.py` 后：
   - 出现 **「知识图谱已启用（导入/执行时将学习接口依赖）」** → 已启用；
   - 出现 **「知识图谱初始化跳过: xxx」** → 未启用（多为缺少 `networkx` 或 pkl 路径不可写）。

2. **调接口查询**  
   请求 **`GET /api/v1/kg/status`**（AI 服务根地址 + 该路径）：
   - 返回 `"enabled": true` 且带 `stats`（节点数、边数）→ 已启用；
   - 返回 `"enabled": false` 且带 `message` → 未启用或异常。

## 存储

- **文件**：`data/knowledge_graph.pkl`（pickle 序列化）
- **结构**：NetworkX 有向图，节点为 API，边为依赖关系

## 自动学习

### 1. 导入接口时

- 批量导入或单增接口后，每个 API 会作为**节点**加入图谱
- 仅建节点，不建边

### 2. 场景用例执行后

- 每次执行场景用例（`test_case_id`）完成后，会从 `param_mappings` 提取依赖
- **仅当本次执行整体 success** 时，才会增加 `success_count`
- 失败时仍会写入边，但 `success_count` 不增加，便于后续按置信度过滤

## 手动初始化历史

若已有大量场景用例，可一次性从历史构建图谱：

```bash
# 从项目根目录执行
python scripts/build_kg_from_history.py

# 仅处理指定项目
python scripts/build_kg_from_history.py --project your-project-id
```

会扫描 `test_cases` 的 steps 和 param_mappings，将依赖写入图谱，来源标记为 `manual`。

## 生成时增强（阶段二）

- 在「一键生成测试用例」时，会从图谱中取出与当前候选 API 相关、且 **置信度 ≥ 0.5**（success_count/count）的依赖边
- 这些边会以「知识图谱：常见依赖关系」的形式追加到给大模型的 prompt 中
- 模型被要求优先参考图谱中的接口顺序与字段映射，无冲突时沿用，有更优方案可灵活调整
- 若图谱为空或未启用，生成逻辑与之前完全一致，不影响现有功能

## 执行时利用图谱（阶段三）

### 3.1 场景用例执行前补全映射

- 在调用执行引擎前，若当前是场景用例（带 `test_case_id`）且图谱可用，会对 `steps` 做一次**映射补全**：
  - 对每一步，从图谱查询该 API 的**前置节点**（入边），且置信度 ≥ 0.5；
  - 若某前置节点就在当前步骤列表中，则自动补上对应的 `param_mappings`（如 Authorization、sessionId 等）；
  - 仅补当前步骤中尚未声明的映射，不覆盖已有配置。

### 3.2 单接口流水线依赖解析

- 在「单接口测试」的依赖解析（`_resolve_dependencies`）中，会**优先查知识图谱**：
  - 以当前目标接口为节点，查询其前置依赖（谁在历史上常在其前调用）；
  - 若图谱返回非空且置信度 ≥ 0.5，则直接用这些前置接口构建依赖链并插入步骤，**不再走 RAG + AI**；
  - 若图谱无结果，则回退到原有 RAG 检索 + AI 分析流程。

## 质量与修正（阶段四）

### 4.1 可学习的成功判定

- 只有**本次执行整体 success** 时才会增加边的 `success_count`。
- 场景执行的 success 已包含：每步 HTTP 状态符合预期 + 若有 `expected_response_body` 则做响应体断言，全部通过才算该步 success。即「可学习」= 全部步骤 success（含 HTTP 与响应体断言）。

### 4.2 失败时降低置信度

- 执行失败时仍会记录到图谱（`count` +1），但 `success_count` 不增加；且**若边已存在则 success_count 减 1**（不低于 0）。
- 反复失败会使该边置信度下降，低于阈值（如 0.5）后不再参与生成与执行补全，相当于自动淡出错误链路。

### 4.3 管理接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/projects/{project_id}/kg/export` | 导出该项目子图（节点+边），便于人工检查或备份 |
| DELETE | `/api/v1/projects/{project_id}/kg/edges` | 删除一条边，Body: `{ "from_api": "project_id:POST:/api/login", "to_api": "project_id:GET:/user" }` |
| POST | `/api/v1/projects/{project_id}/kg/rebuild` | 从该项目历史 test_cases 重建图谱（先清空该项目节点再按用例重新写入） |

## 依赖与故障

- 图谱初始化失败不会影响主流程（导入、执行、生成照常可用）
- 需要 `networkx`，项目 `requirements.txt` 已包含
